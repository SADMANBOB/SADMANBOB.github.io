# C&G structured data model

Generated by `shared/localBusinessSchema.js` plus each site's
`src/content/seo.js`, and asserted by `scripts/verify-sites.mjs`.

## Entities and ownership

Two businesses are described. They are never merged into one entity, because
home inspection and contracting are separate services under the 12-month
separation policy, and merging them would imply a single vendor performing both
on the same property.

| Entity | `@id` | Type |
| --- | --- | --- |
| C&G Certified Home Inspector | `{origin}/#business` | `ProfessionalService` |
| Coastal Construction Services | `{origin}/contracting/#contractor` | `GeneralContractor` |

### Why `ProfessionalService` for the inspector

A home inspection is an advisory service; the inspector performs no
construction. `HomeAndConstructionBusiness` would be a more specific type but it
would misrepresent the work and blur the inspection/contracting boundary.
Schema.org has no home-inspection subtype, so the nearest accurate
`LocalBusiness` subtype is used.

### Why the contractor node is named for the contractor of record

The owner approval of 2026-07-23 states:

> C&G Contracting Services is the public-facing brand for contracting work
> performed by Coastal Construction Services, CSLB #987643.

and expressly does **not** assert that C&G is a DBA, division, company, or
separate legal entity. The node is therefore named `Coastal Construction
Services` with `alternateName` `C&G Contracting Services`, and the approved
disclosure is carried verbatim in `description`.

The CSLB licence is attached to this node only. It is never attached to the
inspection entity, and `verify-sites.mjs` asserts both that the inspection node
has no `hasCredential` and that the inspection graph never contains the licence
number at all.

`hasCredential.recognizedBy` names the California Contractors State License
Board, so the licence reads as a credential issued by the state rather than a
self-assertion, and `url` links the official lookup record.

## Published fields

Inspection entity: `name`, `url`, `telephone`, `email`, `image`, `logo`,
`description`, `serviceType`, `areaServed`.

Contracting entity: `name`, `alternateName`, `url`, `telephone`, `email`,
`description`, `identifier` (CSLB PropertyValue), `hasCredential`, `areaServed`,
`sameAs` (official licence lookup only).

`description` on the inspection entity reuses the published meta description
verbatim, so structured data never states anything the page does not say.

## Deliberately omitted

| Field | Reason |
| --- | --- |
| `address`, `geo` | No street address or coordinates are approved. Inventing either is a false local-search signal. |
| `openingHours` | No hours are approved. |
| `priceRange` | No pricing is approved. |
| `aggregateRating`, `review` | No review has passed the review registry, so there is nothing to aggregate. |
| `foundingDate` | No defensible start date is confirmed. |
| `numberOfEmployees`, `founder`, `employee` | Not confirmed. |
| `makesOffer`, `hasOfferCatalog` | Would imply fixed published services or pricing. |
| `sameAs` (social/directory) | No social or directory profile is confirmed. Only the CSLB lookup is allowed. |

`scripts/verify-sites.mjs` walks **every** node of **every** emitted JSON-LD
document and fails the build if any of these appear, so the restriction cannot
be bypassed by adding a field on a page nobody checks by name.

## Service areas

`areaServed` is built from `approvedServiceAreas("Metadata")`, so a county
enters structured data only when its `approvedForMetadata` flag is true. Today
that is Los Angeles County and Riverside County. The City of Compton remains
pending and is therefore absent.

Only counties are published, never individual cities. Cities appear in page copy
as representative communities, and emitting one node per city would imply a
physical presence in each.

`areaServed` was previously banned outright by the verifier. That blanket ban
predated the `approvedForMetadata` flag, which exists precisely to authorise
this. The ban is now a value check: the field is allowed, but every value must
be a metadata-approved area, and `aggregateRating`/`reviewRating` remain banned
unconditionally.

## Placement

The inspection business node is emitted on `/inspection/` and on each county
service-area page, which are the local-intent entry points. The root chooser
remains service-neutral. The contracting node is emitted on the contractor home
route. Every copy shares one `@id`, and the verifier asserts that two definitions
of the same `@id` are identical, so the pages can never describe the same entity
in contradictory ways.

## Open owner decision

Publishing a business address would make the inspection entity eligible for
local-pack treatment that a service-area business without an address generally
does not receive. No address is approved. If the owner wants to publish one, it
belongs in `shared/siteData.js` behind the same approval gate as every other
fact, and `address` must then be removed from the prohibited-field list.
